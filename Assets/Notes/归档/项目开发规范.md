# 《深入地牢》项目开发规范

> 适用范围：本规范面向后续所有人类与 AI 开发任务。目标是保护“四层协作”边界，让九宫格领域规则、业务内容与表现实现长期可维护。

---

## 1. 当前架构分层

```text
Presentation 表现层
  只处理输入、视图、动画、音效、VFX、UI、镜头、手感。

Game Logic / Content 业务内容层
  只写具体怪物、机关、道具、遗物、房间卡、数值与内容规则。

Domain Infrastructure 项目级领域基础设施
  固定《深入地牢》的九宫格、实体卡、堆叠、翻面、互动、伤害、行动计数、领域事件。

Foundation Infrastructure 通用基础设施
  保留跨项目地基：ModelDb、AbstractModel、IRng、ActionQueue、Run/Room/Save 骨架等。
```

### 硬边界

- `Game.Core` 必须保持纯 C#，不得引用 `UnityEngine`。
- `Game.Presentation` 可以引用 Unity，但不得直接改领域状态。
- 后续 `GameLogic/Content` 只能调用 Domain API，不得直接篡改 `CardInstance` 的 `Zone`、`Coord`、`StackIndex`、`IsFaceUp`。
- 所有随机规则必须来自 `IRng` / `DeterministicRng`。
- 所有表现触发必须来自 `DomainEvent`，业务代码不得直接调用 Tween / VFX / Audio。

## 3. 九宫格领域规则

- 九宫格固定 3×3，格位编号 1~9，行优先。
- 玩家默认出生格为格 8。
- 每格是卡堆，`GridCell.TopCard` 是唯一普通互动目标。
- 玩家移动到空格：移动玩家卡，计 1 次玩家行动。
- 玩家与正面朝上的非玩家顶牌互动：玩家位置不变，计 1 次玩家行动。
- 玩家正交相邻格的顶牌自动翻开。
- 顶牌移除后，下方顶牌自动翻开。
- 怪物被移除默认给 10 金币。
- 机关对玩家的接触伤害为固定伤害，不吃玩家防御。

任何改变格子、堆叠、翻面、Zone 的逻辑必须通过 `GridState` 或领域 Action 完成。

---

## 4. 业务内容开发规则

AI 新增怪物、机关、道具、遗物、房间卡时：

1. 先确认是否已有 Domain API 可表达需求。
2. 只通过 `DomainFacade`、`GridState` 操作方法、`CombatResolution`、领域事件扩展点表达规则。
3. 不得自己维护第二套坐标、行动计数、翻牌、移除或金币奖励规则。
4. 若现有 Domain API 不够，必须在任务说明中提出“需要新增领域 API”，不得绕开。
5. 每个新内容至少配一个 Core 测试或一个确定性 seed 回归脚本。

---

## 5. 表现层接入规则

表现层标准链路：

```text
玩家输入 → PlayerIntent → DomainFacade.SubmitIntentAsync → DomainEventBatch → Presentation Orchestrator → Manifest/Cue/Recipe
```

禁止链路：

```text
CardView / Controller → 直接扣血、给金币、翻面、移除、播放业务专属特效
```

表现层只读领域事件和只读快照。若表现缺失，应补 Manifest / Orchestrator / Recipe，而不是在业务类里补播放代码。

---

## 6. 测试规范

### 必跑项

- 修改 `.cs` 后必须触发 Unity 编译。
- 当前默认验证工作流是“编译通过即验证”；不要进入 Test Runner 执行 Edit Mode 自动化测试。
- 修改领域不变量时，必须更新 `DomainInvariantValidator`，并在交付说明中写清验证路径。

### 当前禁用项

- AI 不得通过 Unity Test Runner、MCP `run_tests` 或其他自动化入口执行 Edit Mode 测试。
- 历史文档里提到的 `Game.Core.Tests` / `Game.Content.Tests` EditMode 回归，统一视为旧流程，除非人类明确要求恢复。

### P0 已覆盖测试方向

- 格位编号与正交查询。
- 卡堆、顶牌、Zone、StackIndex。
- 玩家移动、行动计数、相邻揭示。
- 玩家互动后位置不变。
- 非法互动拒绝且不计行动。
- 移除顶牌后下方顶牌翻开。
- 怪物/机关基础伤害。
- 九宫格不变量验证。

## 7. 文档与交付要求

- 新增系统性规则：先更新设计/规范文档，再实现。
- 新增内容规则：在内容文件或任务说明中写清触发事件、需要的 DomainEvent、测试覆盖。
- 交付说明必须包含：改动路径、验证结果、未决设计问题。
- 不要覆盖用户未提交的 Notes、场景、Prefab、材质或渲染资产。

---

## 8. 需要人类审核的变更

以下变更必须升级给人类确认：

- 修改九宫格编号、出生格、行动计数语义。
- 修改自动翻牌、移除连锁、清场、金币奖励规则。
- 修改 `DomainEventType` 的语义或表现事件契约。
- 修改存档格式、RNG、ModelDb、ActionQueue 等基础设施。
- 业务代码需要新增领域公共 API。
- 表现层需要新增 required Cue。
