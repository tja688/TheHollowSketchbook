## 3. 当前面板的组织结构

面板目前按“渲染阶段 / 责任层”分页面组织：

### 3.1 总览
职责：
- 快速判断当前是哪一层在主导画面
- 快速定位各层对画面的影响
- 展示当前关键资产接线关系

### 3.2 低清画布 / URP 基线
职责：
- 管理 Render Scale
- 管理 Upscaling Filter
- 管理 HDR / Depth Texture / Opaque Texture 等 URP 基线
- 管理主光阴影 / 附加灯阴影 / Local Shadows / Soft Shadows 等阴影总开关
- 管理 Shadow Distance、主光阴影分辨率、附加灯阴影图集、附加灯各分辨率档位、Depth Bias / Normal Bias
- 管理当前封档使用的固定虚拟分辨率档位（960×540 / 640×360 / 1280×720）

### 3.3 Phase 05 / RetroFakeLit
职责：
- 批量管理普通物体假光照材质的共享参数
- 统一调阴影色、环境亮度、分段、远景雾、高光风格

注意：
- 这里不是逐材质精修面板
- 这里只适合改“共享风格参数”
- 不适合统一改每个材质自己的底图和 BaseColor

### 3.4 RetroFakeLitConvert
职责：
- 一键把文件夹里的模型或当前场景选择转换为 `RetroFakeLit`
- 自动递归探索文件夹结构，识别 `gltf/fbx/obj/glb` 等模型源
- 自动判断是单模型还是多模型，并为每个模型产出 prefab
- 对场景对象立即替换为新 prefab 实例，方便立刻看效果
- 在面板内保留 Debug 栏，显示成功摘要与失败原因

### 3.5 Phase 07 / 暗部阈值 LUT
职责：
- 控制 `RetroPosterizeThreshold` 全屏 Pass
- 用于控制暗部统一染色

### 3.6 Phase 08 / Retro Composite
职责：
- 管理镜头损坏、颗粒、色散、暗角、量化、冷暖偏色、虚拟画布采样
- 负责最终复古调味
- 包含 Bloom（URP Volume）控制区

### 3.7 预设 / Presets
职责：
- 一键切换整套渲染风格（同时覆盖 Phase 07、Phase 08、Bloom）
- 保存当前参数为新预设资产
- 生成四组官方默认预设

## 4. 当前架构形态

当前面板采用：
- `EditorWindow`
- `UI Toolkit`
- Odin 仅用于配置资产的 Inspector 表达与自动填充按钮，不承担主窗口绘制

### 4.1 为什么这样做

这样分工的原因是：
- 主窗口需要完整自定义布局、页面导航、说明文案、可扩展结构，所以用 UI Toolkit
- 配置资产适合用 Odin 做引用管理和辅助按钮，所以保留 Odin
- 这样后续继续接更多渲染阶段时，扩展成本更低

### 4.2 数据流

当前窗口本身**不保存渲染参数副本**。
它做的是：
- 读取真实项目资产
- 修改真实项目资产
- 直接写回真实项目资产

也就是说，面板本质上是一个“项目渲染资产控制前端”。

## 5. 如何日常使用这个面板

推荐顺序：

### 5.1 快速分层排查
1. 打开“总览”，查看当前各层关键参数
2. 若怀疑暗部染色问题，去 `Phase 07 / 暗部阈值 LUT`
   - 关闭 `RetroPosterizeThreshold Feature`，观察画面变化
   - 切换 LUT，调整 `Contribution` 和 `Threshold`
3. 若怀疑整体复古调味问题，去 `Phase 08 / Retro Composite`
   - 关闭 `CardDungeon Retro Composite Feature`，观察画面变化
   - 调整 `PaletteStrength`、`WarmTint`、`Saturation` 等参数
4. 若怀疑阴影根本没出来，去 `低清画布 / URP 基线`
   - 先看 `Main Light Shadows` / `Additional Light Shadows` / `Local Shadows`
   - 再看 `Shadow Distance`
   - 若阴影有但发糊或悬浮，再看 `Main Light Shadow Resolution`、`Additional Shadow Atlas`、`Depth Bias`、`Normal Bias`
5. 若怀疑 Bloom 过强导致全场泛光，去 `Phase 08 / Retro Composite` 底部的 Bloom 区
   - 提高 `Threshold`，降低 `Intensity`
6. 若需要快速切换整套风格，去 `预设 / Presets` 页面
   - 一键应用 Clean Debug / Default Retro / Dark Horror / Combat Readability

### 5.2 调整体复古感
优先顺序建议：
1. `低清画布 / URP 基线`
2. `Phase 05 / RetroFakeLit`
3. `Phase 07 / 暗部阈值 LUT`
4. `Phase 08 / Retro Composite`
5. `预设 / Presets`

原则：
- 先定画布粗糙度
- 再确认阴影有没有、阴影距离和清晰度是不是在合理区间
- 再定物体材质质感
- 再定暗部统一风格
- 再调 Bloom（只让信息点发光）
- 最后加镜头和脏感

### 5.3 Phase 09 当前封档方式
当前没有额外接入运行时 `FixedVirtualResolutionController`。
本次 Phase 09 采用的是：
- `Assets/VisualPrototypes/InscryptionRetro/Materials/M_RetroComposite_Inscryption.mat` 中的 `_VirtualWidth/_VirtualHeight/_Pixelate`
- 配合 `Assets/Settings/URP-HighFidelity.asset` 中的 `Render Scale`
- 由控制台统一提供 3 档固定虚拟分辨率快捷按钮

当前封档主档：
- `960×540`
- `Pixelate = 1`
- `Render Scale = 0.5`
- `Upscaling Filter = Point`

这意味着：
- 当前核心视效已经把“统一像素颗粒档位”纳入控制台维护范围
- 但当前并**没有**实现运行时黑边、TargetTexture 输出链、鼠标坐标映射
- 因为这次明确排除了 06 卡牌和后续交互实现，所以这里不再继续扩后续开发建议

## 6. 如何开发这个面板

## 6.1 新增一个页面

在 `CardDungeonRenderPipelineConsoleWindow.cs` 中：

1. 给 `ConsolePage` 增加枚举项
2. 在 `BuildNavigation()` 里新增导航按钮
3. 在 `RefreshPage()` 里接入新的 `BuildXXXPage()`
4. 新写一个页面构建函数，例如：

```csharp
private void BuildPhase09Page()
{
    AddPageTitle("Phase 09 / 固定虚拟分辨率", "说明...");
    contentScroll.Add(CreateSectionCard("分组标题", "分组说明", section =>
    {
        // 控件
    }));
}
```

---

## 6.2 新增一个控制项

当前推荐复用已有控件包装函数：
- `CreateFloatControl`
- `CreateIntControl`
- `CreateToggleControl`
- `CreateColorControl`
- `CreatePopupIntControl`
- `CreateObjectFieldControl`
- `CreateSectionCard`

要求：
- 每个控制项都写清楚作用
- 说明“改大怎样、改小怎样”
- 不要只写技术名，不写效果后果

这是这个面板最重要的可维护性原则之一。

## 6.3 新增一个被控制资产

如果后续新阶段需要接入新的材质 / Renderer Feature / ScriptableObject：

1. 先把引用加入 `CardDungeonRenderPipelineConsoleConfig.cs`
2. 在 `AutoPopulate()` 中补默认路径
3. 在窗口对应页面里接 UI
4. 确保改动直接写回真实资产

## 6.4 RetroFakeLitConvert 维护约定

当前 `RetroFakeLitConvert` 的实现入口：
- `Assets/_Project/Editor/Rendering/RetroFakeLitConversionService.cs`
- `Assets/_Project/Editor/Rendering/CardDungeonRenderPipelineConsoleWindow.cs`

它当前支持两类输入：
1. Project 里的源文件夹
2. 当前场景 Hierarchy 里的选择对象

处理规则：
- 文件夹输入会递归扫描 `gltf / glb / fbx / obj / dae / blend`
- 如果文件名是 `scene/model/default` 这类通用名，会优先用父文件夹名生成 prefab 名
- 输出 prefab 默认写到 `Assets/Arts/Prefabs/RetroFakeLits`
- 生成的 RetroFakeLit 材质写到 `Assets/_Project/Rendering/Materials/RetroFakeLitGenerated`
- 场景对象处理后会直接 `SaveAsPrefabAssetAndConnect`，所以场景表现会立刻切成新 prefab
- 失败原因会写到页面内 Debug 栏，也会进 Unity Console

维护时注意：
- 不要直接改 YAML；继续通过 Unity API 改 prefab 和场景对象
- 如果后续需要支持更多模型格式，只补转换服务里的扩展名白名单与识别逻辑
- 如果后续想给不同类型模型套不同默认 tint，优先改 `PresetTint()`，不要把 UI 面板先做复杂

---

## 6.5 如果需要新增“预设 / 快照 / 回滚”

建议后续单独扩一层：
- 不要把预设硬编码到窗口状态里
- 建议做独立 ScriptableObject 预设资产
- 面板只负责：应用预设 / 保存当前为预设 / 比较差异

这样不会污染当前“面板只控制真实资产”的简单结构。

## 7. 当前维护注意事项

### 7.1 先读真实资产，再改 UI
不要先凭印象改窗口控件。
如果渲染资产字段、Shader 属性名、Renderer Feature 名称变了，先确认真实项目状态。

### 7.2 这个面板依赖若干硬编码路径
当前 `AutoPopulate()` 依赖固定路径。
如果下列资产改名或挪位置，要同步更新：
- `URP-HighFidelity.asset`
- `URP-HighFidelity-Renderer.asset`
- `M_RetroPosterizeThreshold_Phase07.mat`
- `M_RetroComposite_Inscryption.mat`
- LUT 路径

### 7.3 Feature 名称也是接线点
当前通过名字查找 Renderer Feature：
- `RetroPosterizeThreshold`
- `CardDungeon Retro Composite`

如果你改了 Feature 名称，面板也要同步改。

### 7.4 当前 URP Upscaling Filter 有项目特例
当前项目里 `URP-HighFidelity.asset` 的 `m_UpscalingFilter` 序列化值是 `4`。
这和常规枚举 `0~3` 不完全一致。
所以当前面板保留了一个：
- `4 - 当前项目值`

后续如果确认了这个值在你当前 Unity/URP 版本里的真实语义，再统一收敛映射逻辑。
在没确认前，不要擅自假定它就是某个标准枚举值。

### 7.5 当前 Phase 05 是“批量共享参数”模式
`RetroFakeLit` 页面现在不是逐材质编辑器。
它会把一组共享参数批量写回全部 `CardDungeon/RetroFakeLit` 材质。
所以如果未来某些物体需要特殊例外：
- 要么做材质分组
- 要么增加“只作用某类材质”的筛选层
- 要么像当前 `Assets/Tests/render.unity/人物立牌`、`Assets/Tests/render.unity/小猫雕像` 一样，保留单独材质做定向风格修正
- 不要直接把当前批量逻辑改得过于复杂

### 7.6 阴影排查现在优先看控制台
当前 `低清画布 / URP 基线` 页面已经额外接入：
- 主光阴影 / 附加灯阴影 / Local Shadows / Soft Shadows
- Shadow Distance
- 主光阴影分辨率
- 附加灯阴影图集分辨率
- 附加灯 Low / Medium / High 三档单灯阴影分辨率
- Shadow Depth Bias / Shadow Normal Bias

推荐排查顺序：
1. 先确认总开关是不是开着
2. 再看距离是不是太小
3. 再看分辨率是不是太糊
4. 最后才动 Bias，避免把“没有阴影”和“阴影悬浮”混成一个问题

## 8.1 预设系统说明

预设资产 `RetroRenderPreset` 是一个 ScriptableObject，同时保存：
- Phase 07 全部参数（LUT、Contribution、Threshold 等）
- Phase 08 全部参数（Vignette、Noise、Palette、WarmTint 等）
- Bloom 参数（Threshold、Intensity、Scatter、Tint）
- 两个 Renderer Feature 的开关状态

应用预设时，所有参数会**一次性写回**对应材质、Renderer Feature 和 Volume Profile。

### 四组官方预设

| 预设 | 用途 | 特征 |
|---|---|---|
| Clean Debug | 调试、检查资产原始状态 | 低风格化、高可读、轻 Bloom、无扫描线 |
| Default Retro | 当前项目默认风格 | 与 `SetCompositeDefaults` + `SetPhase07Defaults` 一致 |
| Dark Horror | 恐怖氛围、阴冷房间 | 重暗角、高对比、冷色调、强 Palette、重噪声 |
| Combat Readability | 战斗场景、需要高可读 | 低扫描线、低噪声、高饱和度、Bloom 强调信息点 |

### 保存自定义预设
在 `预设 / Presets` 页面点击“保存当前为新预设”，会把当前所有参数捕获为新的 `.asset` 文件。

---

## 8.2 Bloom 控制说明

Bloom 参数存储在 URP Volume Profile（`SampleSceneProfile.asset`）中，而不是材质里。

面板中的 Bloom 控制区直接修改 Volume Override，**不需要改 shader**。

参考计划建议值：
- Threshold: 0.9 - 1.2（只让高亮像素发光）
- Intensity: 0.15 - 0.45（不要照亮全场）
- Scatter: 小（光晕集中）

当前项目 Volume 中的默认值（Intensity=1.35）**明显高于参考建议**。如果画面出现“整张桌子发光”，优先去 Bloom 区收敛 Intensity。

## 8.3 AI 自动化调试可用性

当前 AI 直接可操作且较友好的部分：
- `Assets/Settings/URP-HighFidelity.asset`：Render Scale / Upscaling / HDR / Depth / Opaque / Shadow Distance / 阴影总开关 / 阴影分辨率 / Bias
- `Assets/Settings/URP-HighFidelity-Renderer.asset`：Feature 开关
- `Assets/_Project/Rendering/Materials/M_RetroPosterizeThreshold_Phase07.mat`：07 参数
- `Assets/VisualPrototypes/InscryptionRetro/Materials/M_RetroComposite_Inscryption.mat`：08 与当前 Phase 09 虚拟分辨率参数
- `Assets/Settings/SampleSceneProfile.asset`：Bloom
- `Assets/_Project/Rendering/Presets/*.asset`：预设、封档

当前 AI 不能直接替你完成验证的部分：
- 不同显示器真实输出一致性
- 最终构建包中的黑边表现
- 鼠标在 letterbox / pillarbox 情况下的真实点击映射
- 运行时交互是否因未来 TargetTexture 链路而偏移

因此当前结论是：
- 对“核心视效调参、排查、封档、回滚”来说，AI 自动化调试已经可用且友好
- 对“真正完整的运行时固定分辨率系统验收”来说，仍需要你手动在 GameView / Player 中确认

## 9. 当前封档总结

当前阶段封档的核心视效实现是：
- URP 基线低清输出
- Phase 05 RetroFakeLit 非 PBR 假光照
- Phase 07 暗部阈值 LUT 统一染色
- Phase 08 Retro Composite 统一镜头脏感、量化、暗角、噪声、虚拟像素采样
- Bloom 仅作为信息点发光补充
- 控制台统一提供预设、封档与调试入口

推荐封档动作：
- 在控制台 `预设 / Presets` 页面点击“封档当前核心效果”
- 生成/覆盖 `Assets/_Project/Rendering/Presets/Retro_Archive_Current.asset`

一句话维护原则：

**以后如果画面跑偏，先回到 Archive 预设，再按 低清画布 → Phase 05 → Phase 07 → Phase 08 → Bloom 的顺序逐层排查。**

## 10. 一句话总结当前面板

当前这个面板的本质是：

**一个基于 UI Toolkit 的项目级渲染控制前端，用页面化方式，把 URP 基线、Phase 05、Phase 07、Phase 08，以及当前封档形式下的 Phase 09 虚拟分辨率档位统一接到一个地方，并且让每个参数都带效果解释，方便持续调参与维护。**
