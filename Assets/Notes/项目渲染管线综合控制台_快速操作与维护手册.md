## 3. 当前面板的组织结构

面板目前按“渲染阶段 / 责任层”分页面组织：

### 3.1 总览
职责：
- 快速判断当前是哪一层在主导画面
- 快速排查“是不是 07 导致偏色 / 发黄”
- 展示当前关键资产接线关系

### 3.2 低清画布 / URP 基线
职责：
- 管理 Render Scale
- 管理 Upscaling Filter
- 管理 HDR / Depth Texture / Opaque Texture / Shadow Distance 等 URP 基线

### 3.3 Phase 05 / RetroFakeLit
职责：
- 批量管理普通物体假光照材质的共享参数
- 统一调阴影色、环境亮度、分段、远景雾、高光风格

注意：
- 这里不是逐材质精修面板
- 这里只适合改“共享风格参数”
- 不适合统一改每个材质自己的底图和 BaseColor

### 3.4 Phase 07 / 暗部阈值 LUT
职责：
- 控制 `RetroPosterizeThreshold` 全屏 Pass
- 用于排查和控制暗部统一染色
- 是当前“屎黄色问题”的第一嫌疑层

### 3.5 Phase 08 / Retro Composite
职责：
- 管理镜头损坏、颗粒、色散、暗角、量化、冷暖偏色、虚拟画布采样
- 负责最终复古调味

## 4. 当前架构形态

当前面板采用：
- `EditorWindow`
- `UI Toolkit`
- Odin 仅用于配置资产的 Inspector 表达与自动填充按钮，不承担主窗口绘制

### 4.1 为什么这样做

这样分工的原因是：
- 主窗口需要完整自定义布局、页面导航、说明文案、可扩展结构，所以用 UI Toolkit
- 配置资产适合用 Odin 做引用管理和辅助按钮，所以保留 Odin
- 这样后续继续接更多渲染阶段时，扩展成本更低

### 4.2 数据流

当前窗口本身**不保存渲染参数副本**。
它做的是：
- 读取真实项目资产
- 修改真实项目资产
- 直接写回真实项目资产

也就是说，面板本质上是一个“项目渲染资产控制前端”。

## 5. 如何日常使用这个面板

推荐顺序：

### 5.1 排查偏色 / 发黄
1. 打开“总览”
2. 看当前 LUT、Contribution、Threshold、WarmTint、PaletteStrength
3. 去 `Phase 07 / 暗部阈值 LUT`
4. 先关 `RetroPosterizeThreshold Feature`
5. 再切 LUT：`DirtyBrown / DarkGreen / CandleRed`
6. 再调 `Contribution`、`Threshold`
7. 如果 07 不是元凶，再去 `Phase 08 / Retro Composite`

### 5.2 调整体复古感
优先顺序建议：
1. `低清画布 / URP 基线`
2. `Phase 05 / RetroFakeLit`
3. `Phase 07 / 暗部阈值 LUT`
4. `Phase 08 / Retro Composite`

原则：
- 先定画布粗糙度
- 再定物体材质质感
- 再定暗部统一风格
- 最后加镜头和脏感

## 6. 如何开发这个面板

## 6.1 新增一个页面

在 `CardDungeonRenderPipelineConsoleWindow.cs` 中：

1. 给 `ConsolePage` 增加枚举项
2. 在 `BuildNavigation()` 里新增导航按钮
3. 在 `RefreshPage()` 里接入新的 `BuildXXXPage()`
4. 新写一个页面构建函数，例如：

```csharp
private void BuildPhase09Page()
{
    AddPageTitle("Phase 09 / 固定虚拟分辨率", "说明...");
    contentScroll.Add(CreateSectionCard("分组标题", "分组说明", section =>
    {
        // 控件
    }));
}
```

---

## 6.2 新增一个控制项

当前推荐复用已有控件包装函数：
- `CreateFloatControl`
- `CreateIntControl`
- `CreateToggleControl`
- `CreateColorControl`
- `CreatePopupIntControl`
- `CreateObjectFieldControl`
- `CreateSectionCard`

要求：
- 每个控制项都写清楚作用
- 说明“改大怎样、改小怎样”
- 不要只写技术名，不写效果后果

这是这个面板最重要的可维护性原则之一。

---

## 6.3 新增一个被控制资产

如果后续新阶段需要接入新的材质 / Renderer Feature / ScriptableObject：

1. 先把引用加入 `CardDungeonRenderPipelineConsoleConfig.cs`
2. 在 `AutoPopulate()` 中补默认路径
3. 在窗口对应页面里接 UI
4. 确保改动直接写回真实资产

---

## 6.4 如果需要新增“预设 / 快照 / 回滚”

建议后续单独扩一层：
- 不要把预设硬编码到窗口状态里
- 建议做独立 ScriptableObject 预设资产
- 面板只负责：应用预设 / 保存当前为预设 / 比较差异

这样不会污染当前“面板只控制真实资产”的简单结构。

## 7. 当前维护注意事项

### 7.1 先读真实资产，再改 UI
不要先凭印象改窗口控件。
如果渲染资产字段、Shader 属性名、Renderer Feature 名称变了，先确认真实项目状态。

### 7.2 这个面板依赖若干硬编码路径
当前 `AutoPopulate()` 依赖固定路径。
如果下列资产改名或挪位置，要同步更新：
- `URP-HighFidelity.asset`
- `URP-HighFidelity-Renderer.asset`
- `M_RetroPosterizeThreshold_Phase07.mat`
- `M_RetroComposite_Inscryption.mat`
- LUT 路径

### 7.3 Feature 名称也是接线点
当前通过名字查找 Renderer Feature：
- `RetroPosterizeThreshold`
- `CardDungeon Retro Composite`

如果你改了 Feature 名称，面板也要同步改。

### 7.4 当前 URP Upscaling Filter 有项目特例
当前项目里 `URP-HighFidelity.asset` 的 `m_UpscalingFilter` 序列化值是 `4`。
这和常规枚举 `0~3` 不完全一致。
所以当前面板保留了一个：
- `4 - 当前项目值`

后续如果确认了这个值在你当前 Unity/URP 版本里的真实语义，再统一收敛映射逻辑。
在没确认前，不要擅自假定它就是某个标准枚举值。

### 7.5 当前 Phase 05 是“批量共享参数”模式
`RetroFakeLit` 页面现在不是逐材质编辑器。
它会把一组共享参数批量写回全部 `CardDungeon/RetroFakeLit` 材质。
所以如果未来某些物体需要特殊例外：
- 要么做材质分组
- 要么增加“只作用某类材质”的筛选层
- 不要直接把当前批量逻辑改得过于复杂

## 9. 一句话总结当前面板

当前这个面板的本质是：

**一个基于 UI Toolkit 的项目级渲染控制前端，用页面化方式，把 URP 基线、Phase 05、Phase 07、Phase 08 这几层真实渲染资产统一接到一个地方，并且让每个参数都带效果解释，方便持续调参与后续扩展。**
