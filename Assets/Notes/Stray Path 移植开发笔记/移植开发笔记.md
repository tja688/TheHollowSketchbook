# Seal The Rift (StrayPath) → Unity 核心移植开发笔记

> 本文档记录移植落地情况、代码结构、使用注意事项与后续开发指南。
> **文档版本**: 1.0 | **代码文件数**: 56 个 C# 文件（新增8个UI + 1个Data）

---

## 1. 项目概述

本次移植基于 `Seal The Rift` 完整设计还原文档（11份，220+KB），将原 Godot 项目的核心系统重新架构并落地到 Unity。

**移植原则**:
- 以设计文档为主要依据，源码仅作实现参考
- 修正原项目中的设计债务（静态全局状态污染、上帝类、硬编码侵入）
- 采用 Unity 原生技术栈，不引入外部依赖（无 UniTask/R3/DOTween）
- 数据驱动：核心配置使用 ScriptableObject，运行时数据用纯 C# 类
- 事件驱动：跨模块通信统一走 GameEventBus

## 4. 关键架构决策与代码注意事项

### 4.1 事件总线使用规范

```csharp
// 订阅（通常在 OnEnable / Start 中）
GameEventBus.Instance.Subscribe<PlayerTurnStartedEvent>(OnPlayerTurnStarted);

// 取消订阅（必须在 OnDisable / OnDestroy 中，防止内存泄漏）
GameEventBus.Instance.Unsubscribe<PlayerTurnStartedEvent>(OnPlayerTurnStarted);

// 发布事件
GameEventBus.Instance.Publish(new PlayerTurnStartedEvent { TurnNumber = 1 });
```

⚠️ **注意**：当前 GameEventBus 使用强引用委托，**订阅者必须在销毁时取消订阅**。后续可优化为 WeakReference 模式。

### 4.2 GameStateManager 状态分层

| 层级 | 类 | 持久化 | 说明 |
|------|-----|--------|------|
| 单局运行时 | `RunState` | ✅ JSON存档 | HP/金币/牌组/遗物/地图/诅咒等 |
| 账户级 | `AccountState` | ✅ JSON存档 | 英雄等级/XP/解锁/设置/排行榜 |
| 战斗内临时 | `BattleTransientState` | ❌ 内存 | 手牌/能量/Block/Buff/Debuff等 |
| 全局配置 | `GameConfiguration` | ✅ JSON存档 | 分辨率/音量/语言 |

**修改RunState后建议立即调用 `GameStateManager.Instance.SaveRunState()`**（保留原设计"即时持久化"意图）。

### 4.3 ScriptableObject 数据配置路径约定

```
Resources/
  StrayPath/
    Cards/        → CardData SO (按CardID命名，如 "1.asset", "25.asset")
    Enemies/      → EnemyData SO (按EnemyID命名)
    Heroes/       → HeroData SO (Hero_DS, Hero_GM, Hero_PG)
    Relics/       → RelicData SO (按RelicID命名)
    Events/       → EventData SO (按EventID命名)
    AIProfiles/   → EnemyAIProfile SO (按EnemyID命名)
    Core/         → GameEventBus.asset
```

### 4.4 卡牌效果注册机制

`CardEffectDispatcher.InitializeEffects()` 中注册所有卡牌效果。推荐模式：

```csharp
// 需目标的敌人效果
_enemyEffects[cardID] = enemy => {
    int dmg = 7;
    enemy.TakeDamage(dmg);
    SetComboActive();
};

// 无需目标的英雄效果
_heroEffects[cardID] = () => {
    var hero = BattleStateMachine.Instance.GetHero();
    hero?.GainBlock(6);
};
```

升级版本使用 `cardID + 1000` 作为键。

### 4.5 敌人AI配置流程

1. 创建 `EnemyAIProfile` SO，配置技能列表与权重
2. 在 `EnemyData` SO 中引用该 AIProfile
3. 将 EnemyData 放入 `Resources/StrayPath/Enemies/`
4. 战斗中 `MapGenerator` / `BattleStateMachine` 通过 EnemyID 加载对应的 EnemyData

### 4.6 遗物触发时机

```csharp
public enum RelicTriggerTiming {
    BattleStart, PlayerTurnStart, PlayerTurnEnd,
    EnemyTurnStart, EnemyTurnEnd,
    CardPlayed, DamageTaken, EnemyKilled,
    NodeEntered, CardDrawn, EnergyChanged, DeckShuffled
}
```

在 `RelicTriggerSystem.InitializeRelicTriggers()` 中注册具体遗物的触发逻辑。

## 5. 后续开发指南

### 5.1 添加新英雄

1. 创建 `HeroData` SO 到 `Resources/StrayPath/Heroes/Hero_XXX.asset`
2. 配置基础属性、初始牌组、等级解锁内容
3. 在 `HeroCombatEntity` 中添加专属被动（如有）
4. 创建英雄专属卡牌 SO（DS 201-233, GM 206-238）
5. 在 `CardEffectDispatcher` 中注册新卡牌效果

### 5.2 添加新敌人

1. 创建 `EnemyData` SO + `EnemyAIProfile` SO
2. 配置技能列表（`EnemyAbilityData`），支持条件、效果、意图
3. 放入 `Resources/StrayPath/Enemies/` 和 `Resources/StrayPath/AIProfiles/`
4. 在 `MapGenerator` 的遭遇配置中按 Act/BattleType 分配（当前在 `CombatRewardSystem` 和 `BattleStateMachine` 中硬编码，建议后续提取为配置表）

### 5.3 添加新卡牌

1. 创建 `CardData` SO，配置所有数值字段
2. 设置 `EffectMethodName` 映射到 `CardEffectDispatcher` 中的方法
3. 在 `CardEffectDispatcher.InitializeEffects()` 中注册效果逻辑
4. 升级版本需要同时注册 `cardID` 和 `cardID + 1000`

### 5.4 添加新遗物

1. 创建 `RelicData` SO，配置触发时机和效果参数
2. 在 `RelicTriggerSystem.InitializeRelicTriggers()` 中注册触发逻辑
3. 如需在战斗代码中实时查询（如 Relic 75 影响 Boost 倍率），使用 `GameStateManager.Instance.HasRelic(id)`

### 5.5 添加新事件

1. 创建 `EventData` SO，配置描述与选项
2. 选项的 `ChoiceType` 决定执行逻辑（在 `MysteryEventSystem.ExecuteChoice` 中扩展）
3. 在 `MysteryEventSystem.eventDatabase` 中加入新事件
