# 杀戮尖塔2 Unity移植 - 阶段1 落地阶段笔记

## 本阶段目标
在不依赖 Unity 场景的前提下，先把可测试的 STS-like 核心逻辑骨架落地，为第二阶段战斗场景与 3D 卡牌交互提供稳定底座。

- 实现基础标识与模型系统：`ModelId`、`AbstractModel`、`ModelDb`

## 已注册的原型内容
### 角色
- `Character:PrototypeHero`
  - 80 HP
  - 3 能量
  - 初始牌组：5 Strike + 5 Defend + 1 Bash

### 卡牌
- `Card:Strike`：1费，单体 6 伤害
- `Card:Defend`：1费，自身 5 格挡
- `Card:Bash`：2费，单体 8 伤害，附加 2 Vulnerable
- `Card:ZapDebug`：1费，单体 3 伤害，抽 1
- `Card:GuardDebug`：0费，自身 3 格挡

### Power
- `Power:Strength`：攻击伤害 +Amount
- `Power:Vulnerable`：受到攻击伤害 *1.5，当前实现向下取整
- `Power:Weak`：攻击伤害 *0.75，当前实现向下取整

### 敌人
- `Enemy:DebugCultist`
  - 首回合给自己 +1 Strength
  - 之后每回合攻击 6
- `Enemy:DebugSlime`
  - 随机攻击 5 或给玩家 1 Weak

### 遭遇 / 章节
- `Encounter:PrototypeCultistEncounter`
- `Act:PrototypeAct`

## 当前结构约束
- `Assets/Game/Core` 不引用 `UnityEngine` / `MonoBehaviour` / `GameObject` / `Transform`
- `Assets/Game/Content` 目前也保持纯 C#，便于后续继续用测试驱动战斗规则
- 第二阶段表现层应只通过 Action / Command / Manager 驱动核心，不要让 UI 直接改 HP、Block、Energy、牌堆

## 第二阶段接力建议
1. 先补 `CombatManager` 标准战斗流程，不碰缓冲区机制
2. 增加 `ImmediatePlayCardAction`，把“从手牌打出”正式接到 Action 系统
3. 用 `PrototypeHero + DebugCultist` 做第一张战斗原型场景
4. 3D 卡牌输入层只提交 `CardPlayRequest`，不要直接调用卡牌效果
5. 若要扩卡，优先继续沿用 `ModelId + CardModel 子类 + StarterContentRegistry` 模式
